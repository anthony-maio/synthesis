Give agents a better way to extend themselves.

Synthesis is a skill-first self-extension system for coding agents.

It treats self-extension as a public operating loop: search installed skills, search the canonical repo, compose a bundle, and only then synthesize a new skill package for review. The goal is not more generated code. The goal is a reusable, governed capability ecosystem.

The Problem

Too many agent systems still treat self-extension as code generation on reflex.

That default duplicates work, hides provenance, and makes governance a cleanup task. Synthesis is built around a narrower, more durable rule: skill discovery and composition come before generation, and new extensions should look like shareable packages that can survive review.

Common failure mode

Generation becomes the operating system.

  • Existing tools are skipped because reuse is not enforced.
  • Fresh code spreads faster than review can keep up.
  • Capabilities live in private transcripts instead of public packages.
  • Trust is inferred after adoption instead of attached to provenance.
Synthesis response

Move extension into a skill economy.

  • Installed and curated skills are searched before anything else.
  • Composition is a real decision point, not a nice-to-have.
  • Fallback synthesis emits a package, not a random function.
  • Promotion runs through GitHub review and automation.
What the artifact becomes

A package another agent can actually pick up.

`SKILL.md` is the anchor. `scripts/`, `assets/`, `references/`, and `agents/` are optional. The package is portable, inspectable, and curation-friendly from day one.

The Loop

One enforced operating loop for self-extension.

01

Search local

Check installed skills before touching the network or drafting anything new.

02

Search canonical

Use the curated GitHub-backed repo as the public source of trusted reusable skills.

03

If one skill is not enough, assemble a small bundle before reaching for synthesis.

04

Draft and submit

Fallback synthesis creates a draft package and a GitHub-ready submission path.

Current path

Skill-first in the package, not just in the pitch.

The active code path now centers on `SynthesisClient.acquire_skill(...)`, a runtime for local install and canonical search, plus an MCP surface that exposes skill-management tools rather than treating generated Python as the final artifact. 

result = await client.acquire_skill(
    "parse csv files",
    requirements="prefer vetted skills"
)

->
PROBATION prepared or submitted
->
TRUSTED merged curated skill

VERIFIED system or elevated

A skill can be scanned, attested, reviewed, and still remain separate from original authorship. Synthesis keeps those claims split on purpose.

Security

We use Ken Huang's STSS as a registry gate, not as a trust shortcut.

The canonical registry now runs STSS in CI when skills are added or changed. That gives Synthesis a concrete security pass for the package snapshot under review without confusing scan status with authorship or curation.

What STSS does here

Scan first. Verify attestations when present.

  • Every changed skill package gets an STSS scan in registry CI.
  • If `attestation.json` exists, the registry also verifies it.
  • The generated catalog records STSS status and signing metadata.
  • Clients can use that data later without taking on a hard dependency.
What STSS does not do

It does not replace provenance or review.

  • `PROVENANCE.json` still records authorship, source, and license.
  • `attestation.json` only speaks for the exact registry snapshot.
  • Mirrored skills can be attested without implying upstream endorsement.
  • Human curation still decides whether a generated or donated skill belongs.
Registry policy

Quality gate, then public curation.

Today the gate is layered: package validation, generated-catalog freshness, tests, STSS scan, optional attestation verification, provenance review, and human judgment. That is deliberate. A signed skill is not automatically a trusted skill. 

PR adds skill
  -> validate package
  -> run tests
  -> stss scan
  -> verify attestation (if present)
  -> review provenance
  -> decide whether to merge

Quick Start

Run the package locally. Gate the registry in CI. Keep the stack light.

Package setup
pip install -e ".[dev]"
pytest -q
synthesis acquire-skill "parse csv files"
Registry security gate
npm install -g stss@0.4.3
python scripts/run_stss_gate.py \
  --base origin/main \
  --head HEAD
Static site workflow
cd website
python -m http.server 8000
